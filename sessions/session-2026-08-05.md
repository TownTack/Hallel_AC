## 2. What was changed this session (all ✅ done + verified)

### A. Client booking form
1. **Past service dates blocked.** `views/public/booking.ejs` date input now has
   `min="<%= new Date().toISOString().slice(0,10) %>"`. Server guard added in
   `middleware/validators.js` (`bookingDate` `.custom()` rejects dates before start-of-today →
   "Service date can't be in the past.").
2. **Location now required.** `middleware/validators.js` has a `lat` rule (checks both `lat`+`lng`
   are finite → "Please pick your service location on the map."). `public/js/booking.js` submit
   guard also blocks when `#lat`/`#lng` empty. NOTE: this rule lives in `bookingRules` which only
   guards `POST /booking`; `POST /api/quote` stays location-optional so job price previews before a
   pin drop.
3. **Custom-quote handling.** Any tank whose price-list entry has `custom: true` (the Rambo
   6,000–10,000 and the >10,000 L Industrial) now makes the booking "custom-pending":
   - Summary card shows **"A custom quote is required"** (not a number) + note
     "You will receive a call soon to scope out the total cost of the service."
   - Pay-now `<select>` forced to `later` and **disabled**.
   - `services/pricing.js#computeQuote` now adds `custom: !!item.custom` to each returned line.
   - Font fix: `.summary-box .total.total-custom` (1.05rem) in `public/css/app.css`, toggled in
     `renderQuote()` so the message isn't rendered in the giant price font.

### B. Pricing / persistence / notifications
4. **Model additions** (`models/Booking.js`): `tankLineSchema.custom` (Boolean) and
   `pricing.customPending` (Boolean).
5. **`routes/public.js` `POST /booking`**: computes `customPending = quote.hasCustom.length > 0`;
   when true forces `payNowChoice='later'`, `effectivePayNow=false`, `payment.method='none'`;
   persists `pricing.customPending` and per-line `custom` (already on `quote.lines`).
6. **SMS copy** (`services/notifications.js`): when `booking.pricing.customPending`, both the client
   confirmation and admin ping replace the "Total GHS X" clause with the call-to-scope message
   (admin variant: "Custom quote — call client to scope the total cost.").
7. **Success page** (`views/public/success.ejs`): custom-pending shows "A custom quote is required"
   + the scope message instead of a numeric total.

### C. Admin dashboard + detail
8. **Card tags** (`views/admin/dashboard.ejs`): green **Paid** badge when `payment.status==='paid'`;
   **Transport** badge now only shows when `!transport.free && status==='unpaid'` (disappears once
   deposit/full confirmed).
9. **Reversible payment confirmation.** `routes/admin.js` `PATCH /bookings/:id/payment` accepts a new
   `mode === 'reset'` → restores `status='unpaid'`, `amountPaid=0`, `amountDue=total`,
   `confirmedManually=false`, clears `confirmedBy/At`, restores `method` (`hubtel` if
   `payNowChoice==='now'` else `none`). `views/admin/booking-detail.ejs` shows the pay buttons only
   when `status==='unpaid'`, otherwise an **"Undo payment confirmation"** button. (admin.js already
   wires every `.js-pay` by `data-mode` — no JS change needed.)
10. **Detail payment display** (`views/admin/booking-detail.ejs`): added **Payment method** row
    (Hubtel (online) vs Cash / pay on-site); pre-confirmation shows either the Hubtel-awaiting note
    ("Payment received from Hubtel — awaiting admin's final confirmation.") or the cash note
    ("Awaiting cash payment confirmation by admin."); post-confirmation keeps the Paid/due +
    "Confirmed by" line. Total row shows "Custom quote required" while custom-pending.
11. **Settle / edit custom quote (new feature).** `routes/admin.js`
    `PATCH /bookings/:id/settle-quote`: sets each custom line's `unitPrice`+`lineTotal`, recomputes
    `tanksSubtotal` → min-callout floor → `total = jobSubtotal + transport.fee`, clears
    `customPending`, updates `amountDue`. Uses `round2` imported from `services/pricing.js`. UI card
    in `booking-detail.ejs` shows **whenever the booking has any custom tank** (not just while
    pending), so a mistaken price is **editable** afterwards — heading/button switch between
    "Settle custom quote"/"Save settled price" and "Edit custom price"/"Update price". Wired via
    `.js-settle` in `public/js/admin.js`.

### D. Distance accuracy (operator's question)
12. **OSRM driving-distance provider added.** `services/distance.js` `osrmDistanceKm()` calls the
    public OSRM router (`https://router.project-osrm.org/route/v1/driving/{lng},{lat};{lng},{lat}`),
    metres→km, falls back to Haversine on any error. `getDistanceKm` switch handles `'osrm'`.
    `models/Settings.js` `distanceProvider` enum now `['haversine','google','osrm']`. Settings page
    + `POST /admin/settings` allow selecting it. Verified: 23.11 km driving vs 20.21 km Haversine on
    a test pair. **Not yet enabled** — operator must set provider to OSRM at `/admin/settings`.
    (Server-side axios call, so no helmet CSP change was needed.)

### E. Admin account security
13. **Chrome "password found in data breach" popup** was NOT a leak — Google Password Manager flags
    the weak default `admin123` because it appears in public breach lists. Fixes:
    - **`scripts/reset-admin.js`** + `npm run reset-admin`: re-hashes `ADMIN_PASSWORD` from `.env`
      onto the existing admin (the seed only runs on an empty Users collection). Refuses weak/default
      passwords (<10 chars or `admin123`/`change-me-now`).
    - **Change-password screen** (this session's last task): `views/admin/settings.ejs` Account card
      (current / new / confirm) → `POST /admin/account/password` in `routes/admin.js`. Validates
      current password, new ≥10 chars, new===confirm, new≠current; bcrypt-hashes and saves. NOTE: this
      route needs `User` — `routes/admin.js` now imports `../models/User` (was missing, caused a 500
      on first run, fixed).
    - `.env.example` hardened with a strong-password note.

## 6. Gotchas reinforced this session

- **`routes/admin.js` needs `require('../models/User')`** for the account route — it wasn't imported
  originally (only Booking + Settings were). Keep it.
- **Password change UI enforces new ≥ 10 chars**, so you cannot set it back to `admin123` (8 chars)
  through the UI — that's by design. To force a specific short value (e.g. restoring test state) use a
  direct `User.hashPassword` script against Mongo.
- Standard existing gotchas still apply (see `CLAUDE.md`): never pass a render local named `settings`
  (Settings doc is `cfg`); `connect-mongo` v6 `.default`; Windows `pkill` doesn't kill Node — free
  port 3000 via `Get-NetTCPConnection ... Stop-Process`.
- OSRM uses the **public demo router** (no uptime/rate guarantee). Fine for this volume; silently
  falls back to Haversine. If a guaranteed provider is wanted later, wire Google (needs a Maps API
  key; code already present in `services/distance.js`).
